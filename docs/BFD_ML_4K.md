# BFD-ML-4K and the current fixed protocol

[中文](BFD_ML_4K_ZH.md)

Dataset: [LotusRosa/BFD-ML-4K](https://huggingface.co/datasets/LotusRosa/BFD-ML-4K). Images are downloaded separately and retain the dataset's own license.

The preparation tool pins upstream commit `81aab6254fe29bdd23d49a36945b1aa2c5ce44c1`. All 4,000 image IDs and four label fields were matched to the current frozen experimental allocation. The upstream release's original directory partitions differ from the allocation below; simply renaming directories would not reproduce it.

| Frozen role | Images | Agent output folder |
|---|---:|---|
| core_train | 2000 | initial/train |
| validation | 400 | initial/val |
| test0 | 400 | initial/safety |
| diagnosis_a | 300 | round_A/train |
| test_a | 100 | round_A/gate |
| diagnosis_b | 300 | round_B/train |
| test_b | 100 | round_B/gate |
| final_test | 400 | Research endpoint only; not imported into ordinary workflow |

[roles.csv](../protocols/bfd_ml_4k/roles.csv) records the frozen roles, public download paths, labels, anonymous groups, and published image hashes. [protocol.json](../protocols/bfd_ml_4k/protocol.json) binds the upstream revision and manifest hashes. The allocation is already fixed, not randomly generated by the Agent. The meaning of the earlier published partitions is preserved in that release.

## Download and prepare initial/A-round data

Using the optional [official Hugging Face CLI](https://huggingface.co/docs/huggingface_hub/guides/cli):

```bash
hf download LotusRosa/BFD-ML-4K --repo-type dataset \
  --revision 81aab6254fe29bdd23d49a36945b1aa2c5ce44c1 \
  --local-dir /absolute/path/BFD-ML-4K

python scripts/prepare_bfd_ml_4k.py \
  --dataset-root /absolute/path/BFD-ML-4K \
  --output /absolute/path/FacadeAgentData
```

In PowerShell, put each command on one line and use native paths such as `D:\Datasets\BFD-ML-4K`. The `hf` CLI is a download helper, not an Agent UI dependency.

The standard-library conversion tool reads the fixed roles, checks metadata and selected image SHA-256 hashes, copies them into a new folder, and writes `labels.csv` with stable image IDs, labels, scenes, and groups. It does not modify the download or overwrite an existing output. Initial and A are selected by default. To include B, specify `--batch initial --batch round_A --batch round_B`. Final is excluded. A failed copy retains its staging directory and does not publish an incomplete output as successful.

Submit `FacadeAgentData/initial`, then `FacadeAgentData/round_A`, through chat and review the reported counts. This is preparation of an existing research protocol; other users must supply their own already-split data.

The local correspondence audit compared metadata without downloading or decoding every image. Running the tool on a downloaded corpus verifies the selected actual file bytes; its successful receipt is the evidence for those output files.
